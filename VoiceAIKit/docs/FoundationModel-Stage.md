# On-device language model stage (prototype)

Status: prototype on `feat/fm-classifier-prototype`. Off by default. The seed pack
does not enable it.

## What it does

Apple's on-device language model (FoundationModels framework) can label an
utterance with one of the pack's intents. It sits behind the existing
`IntentClassifying` contract, so `NLUEngine` and its guards are unchanged.

| Mode (`IntentClassifierMode`) | Pack string | Who labels the turn | When the language model runs |
|---|---|---|---|
| `.packOnly` | `pack_only` | the pack classifier | never (the default) |
| `.packWithFoundationModelFallback` | `pack_with_fm_fallback` | the pack classifier | only when the pack's answer would end in `Default Fallback Intent` |
| `.foundationModel` | `foundation_model` | the language model | every turn (the pack classifier also runs, for comparison) |

In both language model modes the pack classifier's answer is used whenever the language model
gives none: a device without Apple Intelligence, Apple Intelligence turned off,
an unsupported language, a refusal, or an error.

## How a turn flows

1. `FoundationModelCascade.classifyAsync` runs the pack classifier (keyword rules
   plus the TF-IDF head, as before).
2. `pack_with_fm_fallback` only: if the engine would accept that answer, it is returned
   unchanged. The check mirrors the engine: out of scope, under the confidence
   bar (the agreement bar for a corroborated turn), or blocked by the
   out-of-vocabulary guard.
3. `FoundationModelIntentClassifier` asks the model for
   `{ inScope: Bool, intent: <one of the pack labels>, selfRating: 0...1 }`, generated
   in that order. The label is an enum in the output schema, so the model cannot
   answer with anything else. When `inScope` is false the pack's fallback label is
   reported whatever `intent` says: without that step, constrained decoding forced
   an off-topic question ("why is Minnesota famous") onto `Help_Accessories` at a
   self-rating of 0.9. Each turn uses a new session and greedy decoding.
4. The model's answer goes back to the engine with `semanticRescue: false`, so the
   engine's confidence bar, help-marker guard and confirmation gate all apply to it.

The confidence is the model's own rating. It is not calibrated; nothing has
measured how often a 0.8 is right. Measure before trusting it (see below).

### Engine changes

- `IntentClassifying.classifyForTopicSwitch(_:)`, defaulting to `classifyAsync`.
  The topic-switch probe during slot filling now calls it, and the cascade
  answers it with the pack classifier only. A slot answer is not a command.
- After a turn the language model labelled, `oovRatio` returns 0 and
  `calibratedConfidence(for:)` returns nil. The vocabulary guard describes the
  TF-IDF head's blind spots, not the model's, and the model has no distribution
  to re-read.

## Configuration

### From the pack (normal case)

Two additions, both optional. A runtime that predates them ignores them.

`runtime/cascade.json`, a new stage:

```json
{"id": "foundation_model", "enabled": true, "mode": "pack_with_fm_fallback"}
```

`mode` is `pack_only`, `pack_with_fm_fallback` or `foundation_model` (the list is
`spec/bundle/3.0/cascade.schema.json` in IntentClassifier; `IntentClassifierMode` is
tested against it through `Tests/VoiceAIKitTests/Fixtures/foundation_model_modes.json`,
generated by `scripts/ci/emit_contract_fixtures.py`). A missing
stage, `enabled` false, a missing `mode` or an unknown `mode` all mean `pack_only`.

`llm/<language>.json`, the text the model sees, in the pack's language:

```json
{
  "instructions": "…",
  "intent_descriptions": {
    "Cmd.VolumeIncrease": "…",
    "Help_Volume": "…"
  }
}
```

Both keys are optional. The runtime sends `instructions`, then one
`label: description` line per described label. It adds punctuation only, never
words, so the package stays language-neutral.

Both are written by the IntentClassifier pack compiler (`nlu_compiler.content_bundle`):
the text from `content/foundation_model/` (instructions, intent descriptions,
per-language examples), the mode from `foundation_model_mode` in
`language_packs/<lang>/platform.yaml`. `llm/<lang>.json` is in every pack built
since; the cascade stage only when the mode is not `pack_only`. Editing a pack
by hand breaks its checksums.

The seed pack `pack-en-v1.0.61` predates this and carries neither file, so with it
the model sees the labels by name only, and the factory logs
`Language model stage on, but neither the pack … nor an override supplies its text`.

### Development override (before a pack carries it)

```swift
var config = VoiceIntentConfiguration(packProvider: provider, trust: .unverifiedForTesting)
config.foundationModelOverride = FoundationModelOverride(
    mode: .packWithFoundationModelFallback,   // optional; omit to let the pack decide
    logsModelIO: true)                         // text comes from the pack
```

`mode` is optional. Left out, the pack decides (this is how the STT app runs: it
sets only `logsModelIO`). Set, it replaces the pack's mode, so `.packOnly` turns the
language model off even when the pack turns it on. Its `instructions` and
`intentDescriptions` are optional: left out, the pack's `llm/<lang>.json` text is
used; set, they replace that part of it, for trying a prompt change before a pack
carries it. It is ignored when
`trust.refusesDevelopmentPacks` is true, which is how a release build is
configured, so a release build always follows the pack.

## Languages

- The model is asked only when `SystemLanguageModel.default.supportsLocale(locale)` is
  true for the session's locale (`VoiceLanguage.localeIdentifier`), checked every turn.
  Otherwise the pack classifier answers and one line is logged:
  `On-device model not used (locale … not supported by the on-device model)`.
- For every locale other than U.S. English the package puts Apple's phrase
  `The person's locale is <id>.` (for example `de_DE`) at the start of the
  instructions. It is the only text the package adds: Apple asks for this exact
  English sentence, from the model's training, whatever the app's language.
- The rest of the instructions can be English for every language (Apple: "These
  instructions can be in the language you prefer"). The output is a Bool, a label
  and a number, so the model's output language does not matter here.

## Backward compatibility

Nothing about this stage can stop a pack from loading:

- No `foundation_model` stage, `enabled: false`, no `mode`, an unknown `mode`, or a
  `mode` of the wrong type: `pack_only`. (`PackCascade.Stage` decodes `mode`
  leniently; the other keys decode exactly as before.)
- No `llm/<lang>.json`, or one that is unreadable or malformed: no pack text, one
  error logged (`BundleDataLoader.loadLLM`), the pack loads normally.
- An SDK without `FoundationModels`, a device without the model, or a locale it does
  not support: the pack classifier answers.
- An app on an older VoiceAIKit given a new pack: its cascade decoder ignores the
  unknown `mode` key and finds stages by id, and it never reads `llm/<lang>.json`
  (which is in the manifest, so integrity checks pass).

## Observability

```
log stream --predicate 'subsystem == "com.voiceaikit" AND category IN {"FoundationModelCascade","FoundationModelClassifier","NLUDecision"}'
```

- `FoundationModelClassifier`: `verdict intent=… confidence=… latency_ms=…`, and one
  line if the model is unavailable on the device.
- `FoundationModelCascade`: the pack's answer next to the model's for every turn the
  model labelled.
- The debug panel's `stage3Score` shows the model's rating; `winningStage` is 3.

The transcript is never logged, except with `FoundationModelOverride.logsModelIO`
(development override only). Then each turn also logs, under
`FoundationModelClassifier`, lines starting `FM REQUEST utterance`,
`FM REQUEST instructions`, `FM REQUEST schema`, `FM RESPONSE json`, `FM TRANSCRIPT`
(the session transcript the framework built) and `FM ERROR`. Long values are
split into numbered pieces (`[1/3]`, `[2/3]`, …).

## Before enabling it in a pack

Run the honest holdout (the set behind `meta/report_card.json`) through both
modes on a device that has the model, and compare with the pack-only numbers:

- holdout accuracy and macro-F1
- `wrong_action_count`, especially state-changing `Cmd.*` intents
- out-of-scope recall
- latency per turn (p50 / p95), and how often the model was unavailable

Also check the self-rated confidence: bucket it and see whether a 0.8 is right
about 80% of the time. If it is not, a fixed bar of 0.70 means little for this
stage, and state-changing intents should confirm before acting.

## Known limits

- Requires an Apple Intelligence device with Apple Intelligence on and a
  supported language. Everyone else gets the pack classifier.
- The model changes with OS updates, outside this package's control. Adapter
  fine-tuning is not available from OS 27.
- No calibrated confidence (see above).
- Slot filling still uses the pack's resolver. The model only labels the intent.
