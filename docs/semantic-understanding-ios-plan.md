## What Changed in the Python Repo

The IntentClassifier branch replaces the single TF-IDF pass with a **3-stage classification pipeline**:

| Stage | Trigger | Model | Threshold |
|---|---|---|---|
| 1. Keyword rules | Always first | Hardcoded rules → calibrated confidence | exact=0.97 / contains=0.85 |
| 2. TF-IDF LogReg | If Stage 1 misses | `intent_model.onnx` (baked TF-IDF vectoriser) | 0.70 |
| 3. Semantic fallback | If Stage 2 below threshold | MiniLM-L6-v2 → `semantic_head.json` | 0.55 |

New model artifacts in IntentClassifier repo:

| File | Size | Purpose |
|---|---|---|
| `models/minilm-l6-v2.onnx` | 22.8 MB | INT8-quantized MiniLM sentence transformer |
| `models/minilm-vocab.txt` | 230 KB | BERT WordPiece vocabulary |
| `models/semantic_head.json` | 240 KB | Logistic-regression head: `{labels, weights[51×384], bias[51]}` |
| `models/intent_model.onnx` | 4.3 MB | TF-IDF vectoriser + LogReg classifier (ONNX) |
| `scripts/export_coreml.py` | — | Converts ONNX models to Apple CoreML `.mlpackage` |

## Why CoreML Instead of JSON Weights for Stage 2

The old `intent_classifier_weights.json` approach manually extracted sklearn weights
and reimplemented TF-IDF math in Swift — a maintenance burden: any pipeline change
(tokenizer, preprocessing flags) required updating Swift code too.

`intent_model.onnx` has the **TF-IDF vectoriser baked into the ONNX graph as a
string-input node**. When converted to CoreML, the iOS app passes a raw string and
gets class probabilities back — no tokenisation code needed. CoreML also runs on the
Apple Neural Engine (A12+) at ~2 ms vs ~15 ms on CPU.

The JSON weights path is kept as a **fallback** in `IntentClassifierService.swift`
so the app builds and functions if `IntentClassifier.mlpackage` is not yet bundled.

## Phase 0 — Prepare CoreML Artifacts (Mac, One-Time, Offline)

Run these commands in the IntentClassifier repo on `feature/Adv2/AddSemanticUnderstanding-3`:

```bash
pip install coremltools onnxruntime
python scripts/export_coreml.py
```

This produces:
- `models/IntentClassifier.mlpackage` — Stage 2 CoreML model (string input → class probabilities)
- `models/MiniLMEmbedder.mlpackage` — Stage 3 CoreML MiniLM embedder (input_ids/mask → token embeddings)

> **Note:** The MiniLM conversion block in `export_coreml.py` may be commented out.
> Uncomment it before running. The resulting `.mlpackage` may be 30–50 MB.
> Decide if that is acceptable for the app bundle before proceeding.

## Phase 2 — New Swift Files (already implemented on this branch)

### `STT/STT/Services/KeywordMatcher.swift` — Stage 1

Rule-based fast path. Mirrors `_compile_keyword_rules()` and `_is_negated()` in
`IntentClassifier/scripts/nlu/classifier.py`.

- 33 keyword rules covering volume, reminders, memory, messages, device, media
- Match types: `.exact` (full-string, conf=0.97) and `.contains` (substring, conf=0.85)
- Negation detection: scans 30 chars before match for `["not", "don't", "never", ...]`
  — "don't translate this" does NOT fire `Cmd.TranslationStart`
- More specific rules appear first (e.g. "unmute" before "mute")

### `STT/STT/Services/SemanticEmbedder.swift` — Stage 3 embedder

Wraps `MiniLMEmbedder.mlpackage` and implements BERT tokenization.
Mirrors `SemanticFallback._tokenise()` and `_embed_onnx()` in
`IntentClassifier/scripts/nlu/semantic.py` exactly.

- Loads `minilm-vocab.txt` as a `[String: Int]` vocabulary dictionary
- `tokenize()`: lowercase → WordPiece segmentation → `[CLS] + tokens + [SEP]`, max_len=64
- `embed()`: passes `input_ids`, `attention_mask`, `token_type_ids` to CoreML;
  mean-pools token embeddings over non-padding positions; L2-normalises → 384-dim `[Float]`
- `init?()` returns `nil` if either `.mlpackage` or `minilm-vocab.txt` is missing
- Stage 3 skips silently when embedder is nil (graceful degradation)

### `STT/STT/Services/SemanticClassifier.swift` — Stage 3 head

Logistic-regression head over MiniLM embeddings.
Mirrors `SemanticFallback.classify()` in `IntentClassifier/scripts/nlu/semantic.py`.

- Loads `semantic_head.json`: `{labels, weights[51×384], bias[51]}`
- `classify(_ embedding: [Float]) -> (label, confidence)`:
  `logit[i] = dot(weights[i], embedding) + bias[i]` → numerically-stable softmax → argmax
- `threshold = 0.55` (tuned on `semantic_holdout_100.csv`, matches Python `DEFAULT_THRESHOLD`)
- `init?()` returns `nil` if `semantic_head.json` is missing from bundle

## Phase 3 — Updated Swift Files (already implemented on this branch)

### `STT/STT/Services/IntentClassifierService.swift`

Orchestrates all 3 stages.

**New async API:**
```swift
public func classifyAsync(_ text: String) async -> ClassificationResult
// ClassificationResult: { label, confidence, semanticRescue: Bool }
```

**Pipeline:**
```
Stage 1: KeywordMatcher.match(text)         → return immediately if match
Stage 2: CoreML IntentClassifier (primary)  → if confident, return
       : JSON weights TF-IDF (fallback)     → used if .mlpackage absent
Stage 3: SemanticEmbedder.embed(text)       → only when Stage 2 uncertain
         → SemanticClassifier.classify()    → if conf ≥ 0.55, return rescued
Fallback: return Stage 2 result             → NLUEngine routes to GenAI
```

**Stage 2 CoreML input/output contract:**
- Input feature: `"input"` (String) — raw text, no tokenization needed
- Output feature: `"classProbability"` (Dictionary<String, Double>)

### `STT/STT/Services/NLU/NLUEngine.swift`

- `handle(_ text: String)` is now `async` (Stage 3 runs CoreML)
- `handleNewIntent` calls `classifier.classifyAsync(text)`
- `semanticRescue` flag from `ClassificationResult` is threaded into `.fulfill` response

### `STT/STT/Services/NLU/NLUResponse.swift`

- `.fulfill` case gains `semanticRescue: Bool = false`

### `STT/STT/Models/IntentResult.swift`

- `.intent` case gains `semanticRescue: Bool = false`

### `STT/ViewModels/LiveTranscriptionViewModel.swift`

- `nlu.handle(text)` call prefixed with `await`
- `apply(_:utterance:)` destructures `semanticRescue` from `.fulfill` and passes to card

### `STT/Views/TranscriptionResultCard.swift`

- Intent badge shows a brain icon (SF Symbol `"brain"`) when `semanticRescue == true`
  — matches Python CLI's `"🧠 semantic"` annotation

## Graceful Degradation

The app degrades gracefully at every missing artifact:

| Missing artifact | Behaviour |
|---|---|
| `IntentClassifier.mlpackage` | Stage 2 uses JSON weights (existing behaviour) |
| `semantic_head.json` | Stage 3 disabled; TF-IDF result used as-is |
| `minilm-vocab.txt` or `MiniLMEmbedder.mlpackage` | Stage 3 disabled |
| All semantic artifacts | App behaves exactly as before this branch |

## Open Questions / Risks

1. **CoreML MiniLM conversion size**: The `.mlpackage` may be 30–50 MB. Evaluate
   whether this is acceptable for App Store distribution before committing it to the repo.
   Alternative: ONNX Runtime Mobile (SPM) can run `minilm-l6-v2.onnx` directly,
   adds ~8 MB runtime but avoids the conversion step.

2. **CoreML Stage 2 string input**: `export_coreml.py` notes the TF-IDF string node
   "may require a hand-rolled iOS fallback if conversion fails." The JSON weights
   fallback in `IntentClassifierService.swift` is exactly that fallback — it activates
   automatically if `IntentClassifier.mlpackage` is absent or fails to load.

3. **`Cmd.SendMessage - yes` / `Cmd.SendMessage - no` labels**: The classifier has
   these as separate labels, but the NLU engine handles yes/no via `yesNo()` inside
   `handleConfirmation()` — not via the classifier. These labels are intentionally
   ignored by `NLUEngine`; the conversation stays correct.

4. **Keyword rule coverage**: The 33 rules in `KeywordMatcher.swift` cover the most
   common commands. Expand by adding entries to `KeywordMatcher.buildRules()` as
   new command patterns are identified in production logs.
